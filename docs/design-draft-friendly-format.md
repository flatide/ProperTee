# 설계 초안 — 읽기 쉬운 서식: 숫자 모양 `{0.00}`, `TEXT`, `ALIGN_LEFT`·`ALIGN_RIGHT`·`ALIGN_CENTER`

**상태: 결정·구현 — 스펙 v0.31.0** (propertee2-java 0.40.0, fixture 148–150을 고치고 152–154 추가;
propertee-js; TeeBox 1.40.0). §9의 열린 질문은 권장안대로 정했다(각 항목의 "결정"). 트래커 이슈 없음.
2026-10-23, v0.30.0을 배포한 직후 사용자가 지적했다. "파이썬 포매팅이 ProperTee 언어의 의도와 달리
비프로그래머에게 친절하지 않고 어렵게 느껴짐." 이 초안은 v0.30.0 `FORMAT`·`PRINTF`의 `{:spec}`
([design-draft-rounding-format.md](design-draft-rounding-format.md) §4.2)을 대신할 문법을 제안한다.
`ROUND`·`FLOOR`·`CEIL`·`TRUNC`의 `digits`와 동점 규칙은 그대로 둔다. 구현하면서 정한 세부 사항(§3.4의
너비 표, §3.5의 메시지)은 해당 절에 반영했다.

## 1. 문제

v0.30.0의 `{:spec}`은 Python 서식 문법의 부분집합이다. 기호마다 뜻을 외워야 읽힌다.

| 서식 | 읽는 법 |
|---|---|
| `{:>10,.2f}` | `:` 서식 시작, `>` 오른쪽 정렬, `10` 폭, `,` 쉼표, `.2` 소수 둘째 자리, `f` 고정 소수점(fixed)의 약자 |
| `{:08.2f}` | `0`은 0으로 채우기, `8`은 폭. 붙여 쓰면 숫자 `08` 하나처럼 보인다 |
| `{:^6}` | `^`는 가운데 정렬 |

- 결과의 모양이 서식에 드러나지 않는다. `{:,.2f}`를 보고 `1,234.50`을 떠올리려면 규칙을 알아야 한다.
- 부분의 순서가 정해져 있다. `{:.2f>8}`이나 `{:,08}`은 오류다.
- `f`는 영어 약자이고, `<` `>` `^`는 문서 편집기의 정렬 버튼과 이어지지 않는다.

ProperTee의 다른 부분은 비프로그래머가 읽을 수 있게 되어 있다. 단어 키워드(`then`, `end`, `and`),
1부터 세는 인덱스, 스프레드시트와 같은 이름의 대문자 내장 함수(`SUM`, `ROUND`, `LEN`, `TRIM`)가
그렇다. 서식만 프로그래머의 약속을 따른다.

## 2. 비프로그래머가 이미 아는 서식

스프레드시트의 숫자 서식이다. 엑셀 셀 서식의 '사용자 지정' 표시 형식과 `TEXT` 함수가 `#,##0`,
`0.00`, `0.0%`, `000` 같은 모양 문자열을 쓰고, Google 스프레드시트와 LibreOffice도 같은 기호를
쓴다. 프로그래밍 쪽에도 같은 기호가 있다(Java `DecimalFormat`, .NET 사용자 지정 숫자 서식).

모양 문자열은 **결과를 닮았다.** `0.00`은 "소수 둘째 자리까지 쓴 수"처럼 보이고, `#,##0`은 "쉼표를
넣은 수"처럼 보인다. 규칙을 몰라도 짐작할 수 있고, 엑셀을 써 본 사람은 그대로 안다. v0.30.0 초안은
엑셀의 `TEXT(x, "0.00")`을 다른 언어 표(§2)에 적었지만 열린 질문(§8-3)의 선택지로는 내놓지 않았다.

## 3. 제안

### 3.1 숫자 모양

수를 어떤 모양의 글자로 쓸지 `0`, `#`, `,`, `.`, `%`로 그린다.

| 기호 | 뜻 |
|---|---|
| `0` | 숫자 한 자리. 그 자리에 쓸 숫자가 없으면 `0`을 쓴다 |
| `#` | 숫자 한 자리. 그 자리에 쓸 숫자가 없으면 비워 둔다 |
| `.` | 소수점. 뒤에 오는 `0`과 `#`의 개수가 소수 자릿수다 |
| `,` | 정수 부분에 있으면 세 자리마다 쉼표를 넣는다 |
| `%` | 맨 끝에만 쓴다. 100을 곱해서 쓰고 `%`를 붙인다 |

| 수 | 모양 | 결과 |
|---|---|---|
| `3.14159` | `0.00` | `3.14` |
| `3.4` | `0.00` | `3.40` |
| `1234567.891` | `#,##0.00` | `1,234,567.89` |
| `1234567` | `#,##0` | `1,234,567` |
| `87.6` | `0` | `88` |
| `7` | `000` | `007` |
| `0.4567` | `0.0%` | `45.7%` |
| `3.5`, `3` | `0.##` | `3.5`, `3` |

- **반올림**은 `ROUND(x, 자릿수)`와 같다. `PRINT`가 보여 주는 숫자를 기준으로 하고, 동점은 0에서 먼
  쪽으로 간다. `1.005`에 `0.00`은 `1.01`, `-2.5`에 `0`은 `-3`, `9.995`에 `0.00`은 `10.00`이다.
- **정수 부분은 자르지 않는다.** `0`의 개수는 최소 자릿수일 뿐이어서 `1234`에 `000`은 `1234`다. 정수
  부분은 적어도 한 자리를 쓴다. `0.5`에 `#.##`은 `0.5`다.
- **소수 부분의 `#`** 자리에서는 끝의 0을 지운다. `0.0#`에 `3.1`은 `3.1`, `3`은 `3.0`이다. 소수
  자리가 모두 지워지면 소수점도 쓰지 않는다.
- **`%`의 100 곱하기**는 십진 숫자의 자리만 옮기므로 오차가 없다. `0.145`에 `0%`는 `15%`다(이진값을
  곱하는 Python은 `14%`).
- 음수는 앞에 `-`를 붙인다. 0으로 반올림된 값에는 부호를 붙이지 않는다. `-0.004`에 `0.00`은
  `0.00`이다. 0은 부호 뒤에 채운다. `-7`에 `000`은 `-007`이다.
- 큰 수도 지수 표기를 쓰지 않는다. `1e21`에 `#,##0`은 `1,000,000,000,000,000,000,000`이다.
- `Infinity`, `-Infinity`, `NaN`은 모양과 관계없이 `PRINT`처럼 쓴다.
- 정수 부분은 `#`들 다음에 `0`들을 쓰고, 쉼표는 두 기호 사이에만 하나씩 넣는다. 소수 부분은 `0`들
  다음에 `#`들을 쓴다. 다음은 오류다.
  - 다른 글자
  - 순서가 뒤섞인 모양(`0#`, `0.#0`)
  - 소수점 뒤가 빈 모양(`0.`)
  - 정수 부분이 없는 모양(`.00`)
  - 처음이나 끝의 쉼표, 겹친 쉼표(`,0`, `0,`, `0,,0`)

### 3.2 서식 문자열: `FORMAT`·`PRINTF`

함수 이름과 인자는 v0.30.0 그대로다. 자리 표시만 바뀐다.

| 자리 표시 | 뜻 |
|---|---|
| `{}` | 다음 값을 `PRINT`가 보여 주는 그대로 쓴다 (v0.30.0과 같다) |
| `{모양}` | 다음 값(수)을 그 모양으로 쓴다 — `{0.00}`, `{#,##0}` |
| `{{`, `}}` | 글자 `{`, `}` (v0.30.0과 같다) |

```
PRINTF("{}개, 평균 {0.00}점", 3, 3.4)        // 3개, 평균 3.40점
PRINTF("합계: {#,##0}원", 1234567)            // 합계: 1,234,567원
PRINTF("진행률 {0.0%}", 0.4567)               // 진행률 45.7%
PRINTF("주문번호 {00000}", 42)                // 주문번호 00042
line = FORMAT("{#,##0.00}원", 1234567.891)    // "1,234,567.89원"
```

`{1}` 같은 위치 자리 표시는 쓰지 않기로 한다. `{0}`(정수로 반올림)과 `{1}`(첫째 값)이 전혀 다른 뜻이면
헷갈린다. 이름 자리 표시 `{name}`은 모양 기호와 겹치지 않으므로 나중에 넣을 수 있다.

### 3.3 `TEXT(수, 모양)`

수 하나를 모양대로 쓴 문자열을 돌려준다. 이름과 인자 순서가 엑셀의 `TEXT`와 같다.
`FORMAT("{모양}", 수)`와 같은 결과다.

```
PRINT("평균:", TEXT(avg, "0.00"))             // 평균: 3.40
label = TEXT(1234567, "#,##0") + "원"         // "1,234,567원"
```

### 3.4 정렬: `ALIGN_LEFT`, `ALIGN_RIGHT`, `ALIGN_CENTER`

`ALIGN_RIGHT(값, 너비)`는 값을 `PRINT`가 보여 주는 글자로 바꾸고, 너비가 될 때까지 공백을 채운다.
문서 편집기의 왼쪽·오른쪽·가운데 정렬과 같은 뜻이다. 글자가 너비보다 길면 자르지 않는다. 가운데
정렬에서 남는 한 칸은 오른쪽에 둔다(v0.30.0의 `^`와 같다).

```
loop row in [["사과", 3, 1500], ["배", 12, 25000]] do
    PRINT(ALIGN_LEFT(row.1, 6), ALIGN_RIGHT(row.2, 3), ALIGN_RIGHT(TEXT(row.3, "#,##0"), 8))
end
// 사과     3    1,500
// 배      12   25,000
```

**너비는 화면 칸으로 센다.** 그래서 위 예처럼 한글 이름이 든 표도 터미널에서 줄이 맞는다. v0.30.0은
`LEN`처럼 글자 수로 세서 이런 표가 어긋났다. 코드 포인트마다 이렇게 센다.

- 0칸: 결합 문자와 서식 문자(General_Category Mn, Me, Cf), 그리고 앞 글자와 한 음절로 합쳐지는 한글
  중성·종성 자모(U+1160–U+11FF, U+D7B0–U+D7FF). 이 규칙이 먼저라서 U+3099처럼 W이기도 한 결합 문자도
  0칸이다.
- 2칸: East Asian Width가 W 또는 F인 글자(한글 음절, 한자, 가나, 전각 문자, 대부분의 이모지), 그리고
  배정되지 않은 코드 포인트도 W로 치는 한자 영역(U+3400–U+4DBF, U+4E00–U+9FFF, U+F900–U+FAFF,
  U+20000–U+2FFFD, U+30000–U+3FFFD).
- 1칸: 나머지. 짝 없는 서로게이트도 1칸이다.

표는 유니코드 16.0으로 고정했다. Python 3.14의 `unicodedata`(유니코드 16.0)로 만들었고, 0칸 구간 370개와
2칸 구간 123개를 두 런타임에 똑같이 넣었다(Java `value/DisplayWidth`, JS `ZERO_WIDTH`·`DOUBLE_WIDTH`).

TeeBox 화면에서는 같은 표도 정확히 맞지 않는다. 출력 글꼴(SF Mono, Consolas 등)에 한글이 없어서
한글을 다른 글꼴로 그리기 때문이다. 이 문제는 TeeBox 쪽 과제로 남긴다.

너비는 0부터 999까지의 정수다(v0.30.0의 세 자리 상한과 같다). 채울 글자를 고르는 셋째 인자(예:
`ALIGN_RIGHT(code, 5, "0")`)는 지금은 오류로 둔다. 필요하면 나중에 더해도 기존 스크립트가 깨지지 않는다.

### 3.5 오류

엄격하게 실패하고 서식 전체를 값보다 먼저 검사한다. 이 방침과 보고 순서는 v0.30.0과 같다.

| 경우 | 메시지 (예) |
|---|---|
| 알 수 없는 자리 표시 (`{:.2f}`, `{x}`, `{0.0.0}`, `{ 0.00 }`) | `FORMAT() invalid format: {:.2f}` |
| 모양 자리 표시에 수가 아닌 값 | `FORMAT() {0.00} requires a number, got string` |
| `TEXT`의 잘못된 모양 | `TEXT() invalid pattern: '0.0.0'` |
| `TEXT`에 수가 아닌 값 | `TEXT() requires a number, got string` |
| `TEXT`의 세 번째 인자 | `TEXT() takes at most 2 arguments` |
| `TEXT`의 모양이 문자열이 아님 | `TEXT() requires a string pattern` |
| 너비가 0–999의 정수가 아님 | `ALIGN_LEFT() width must be an integer from 0 to 999` |
| `ALIGN_*`의 세 번째 인자 | `ALIGN_RIGHT() takes at most 2 arguments` |

나머지(`missing argument`, `unclosed {`, `unmatched }`, 개수 불일치)는 v0.30.0과 같다. 구현하면서 정한
점:

- `TEXT`의 잘못된 모양은 `TO_NUMBER`의 메시지처럼 작은따옴표로 감싼다. 빈 모양도 `''`로 보인다.
- 너비 메시지는 `ROUND() digits must be an integer`에 맞춰 "integer"라고 쓴다.
- `TEXT`는 서식처럼 모양을 값보다 먼저 검사한다. `TEXT("x", "y")`는 `invalid pattern: 'y'`이다.

## 4. 같은 출력, 두 문법

| 하고 싶은 것 | v0.30.0 | 제안 |
|---|---|---|
| 소수 둘째 자리까지 | `{:.2f}` | `{0.00}` |
| 천 단위 쉼표 | `{:,}` | `{#,##0}` |
| 쉼표와 소수 둘째 자리 | `{:,.2f}` | `{#,##0.00}` |
| 다섯 자리로 0 채우기 | `{:05}` | `{00000}` |
| 퍼센트 | 없음 | `{0.0%}` |
| 10칸 오른쪽 정렬 | `{:>10}` | `ALIGN_RIGHT(값, 10)` |
| 소수 둘째 자리, 10칸 오른쪽 정렬 | `{:>10.2f}` | `ALIGN_RIGHT(TEXT(값, "0.00"), 10)` |

자주 쓰는 위 다섯 줄은 짧아지고 결과를 닮는다. 정렬을 함께 쓰는 표는 더 길어지지만, 함수 이름이 하는
일을 말해 준다. `{:,}`는 소수를 `PRINT`처럼 그대로 두었지만, 모양에서는 소수 자릿수를 정해야
한다(`#,##0.##`).

## 5. 엑셀과 다른 점

엑셀의 숫자 서식에서 수에 필요한 부분만 가져오고, 엑셀에서 헷갈리는 동작은 바꾼다.

- `3`에 `0.##`: 엑셀은 `3.`, 제안은 `3`.
- `0.5`에 `#.##`: 엑셀은 `.5`, 제안은 `0.5`.
- 모양 끝의 쉼표(`#,##0,`): 엑셀은 1000으로 나누어 쓰지만, 제안에서는 오류다.
- 다음은 없다. 글자는 서식 문자열에 쓴다: `{#,##0}원`.
  - 글자를 섞은 모양(`#,##0"원"`)
  - 양수·음수·0을 나눈 모양(`0;-0;0`)
  - 색
  - 날짜 모양
- 수가 아닌 값: 엑셀 `TEXT`는 숫자 글자를 수로 바꾸고 다른 글자는 그대로 돌려주지만, 제안은 숫자
  글자라도 오류를 낸다. ProperTee는 값을 조용히 바꾸지 않는다(`5 == "5"`가 `false`인 것과 같은 원칙).

## 6. 호환성 — spec v0.31.0

**깨지는 변경**이다. v0.30.0의 `{:spec}`은 모두 `invalid format` 오류가 된다. 조용히 다른 결과를 내는
경우는 없다.

- v0.30.0은 2026-10-23에 배포되었다. 이 서식에 기대는 스크립트가 거의 없는 지금이 바꾸는 비용이 가장
  낮다.
- `{}`, `{{`, `}}`와 `PRINTF`·`FORMAT`의 이름·인자, 그리고 `ROUND` 계열은 그대로다.
- 마이그레이션은 §4 표대로 옮기고, 폭과 정렬은 `ALIGN_*`으로 옮긴다.
- 새 내장 함수 넷(`TEXT`, `ALIGN_LEFT`, `ALIGN_RIGHT`, `ALIGN_CENTER`)은 대문자 이름이 예약되어
  있으므로 기존 스크립트와 부딪치지 않는다.

## 7. 기각한 대안

- **두 문법을 함께 두기**(`{:spec}`을 고급용으로 남김): 같은 일을 하는 표기가 둘이면 예제와 문서가
  갈라진다. 비프로그래머가 남이 쓴 스크립트에서 어려운 쪽을 만나게 된다.
- **단어로 된 옵션**(`TEXT(x, {decimals: 2, commas: true})`): 읽기는 쉽지만 길고, 서식 문자열 안에
  넣을 수 없다.
- **기능별 함수만**(`FIXED(x, 2)`, `COMMAS(x)`, `ZERO_PAD(x, 5)`): 함수가 늘고, 둘을 함께 쓰려면
  감싸는 순서를 알아야 한다(`COMMAS(FIXED(x, 2))`).
- **자리 표시 안에 폭과 정렬**(`{0.00, 10}`, `{>10}`): 기호를 다시 외워야 한다.
- **콜론을 남기기**(`{:0.00}`): 위치 자리 표시 `{1:0.00}`을 살릴 수 있다. 하지만 기호가 하나 늘고,
  위치 자리 표시는 비프로그래머에게 필요가 적다.
- **`PAD_LEFT`·`PAD_RIGHT`**(SQL `LPAD`, JS `padStart` 식): 왼쪽을 채우면 오른쪽 정렬이 되어, 이름과
  결과가 반대로 읽힌다.

## 8. 구현 계획

## 9. 열린 질문

2026-10-23 사용자가 "진행해줘"로 권장안을 모두 택했다.

1. **방향**: 엑셀식 숫자 모양(권장) / 단어 옵션 / 기능별 함수. **결정**: 엑셀식 숫자 모양.
2. **v0.30.0의 `{:spec}`**: 없애고 v0.31.0으로 낸다(권장) / 함께 둔다. **결정**: 없앤다.
3. **`TEXT(수, 모양)`**: 넣는다(권장) / `FORMAT("{0.00}", x)`로 충분하다. **결정**: 넣는다.
4. **정렬 함수 이름**: `ALIGN_LEFT`·`ALIGN_RIGHT`·`ALIGN_CENTER`(권장) / `PAD_RIGHT`·`PAD_LEFT`·`PAD_CENTER`.
   **결정**: `ALIGN_*`.
5. **너비 세기**: 화면 칸, 한글 2칸(권장) / `LEN`처럼 글자 수. **결정**: 화면 칸.
6. **`%`**: 넣는다(권장. 엑셀과 같고 비율을 쓸 때 흔하다) / 뺀다(100을 곱한다는 점이 낯설 수 있다).
   **결정**: 넣는다.
7. **`PRINTF`라는 이름**: 그대로 둔다(권장) / 바꾼다. C에서 온 이름이지만 "PRINT + 서식"으로 외우기
   쉽고, 바꾸면 깨지는 변경이 하나 더 는다. **결정**: 그대로 둔다.
