# 설계 초안 — 소수점 자릿수: `ROUND`·`FLOOR`·`CEIL`·`TRUNC`의 `digits`와 서식 출력 `FORMAT`·`PRINTF`

**상태: 결정·구현 — 스펙 v0.30.0** (propertee2-java 0.39.0, fixture 145–151; propertee-js;
TeeBox 1.39.0). §8의 열린 질문은 권장안대로 정했다(각 항목의 "결정"). 트래커 이슈 없음.
2026-10-23 세션 논의에서 출발했다. 소수점 아래 자릿수를 제한해 출력할 방법이 없다는 지적(예: 3.48 →
3.4)에 사용자가 범위를 정했다. 버림·반올림 등 자르는 방식을 모두 제공하고, 숫자 함수에 자릿수 인자를
더하는 방식(A안)으로 가며, `PRINT`에 서식 인자 방식을 추가한다. 구현하면서 정한 세부 사항(§4.2의 `0`
조합과 세 자리 상한, §4.3의 메시지)은 해당 절에 반영했다.

## 1. 문제

스펙 v0.29.0의 정의는 다음과 같다.

> `FLOOR(n)` — Round down · `CEIL(n)` — Round up · `ROUND(n)` — Round to nearest integer

1. **자릿수를 지정할 수 없다.** 세 함수 모두 정수만 만든다. 게다가 `ROUND(3.48, 1)`은 오류 없이
   `3`이다. 두 런타임 모두 두 번째 인자를 조용히 버린다(`FLOOR(3.48, 1)`도 `3`, `ROUND(2.5, 1, 9)`도
   `3`).
2. **곱했다 나누는 우회는 틀린 값을 낸다.** 곱셈이 이진 소수의 오차를 드러낸다.

   ```
   PRINT(FLOOR(0.29 * 100) / 100)   // 0.28 — 0.29 * 100 은 28.999999999999996
   PRINT(FLOOR(4.35 * 100) / 100)   // 4.34 — 4.35 * 100 은 434.99999999999994
   PRINT(ROUND(1.005 * 100) / 100)  // 1    — 1.005 * 100 은 100.49999999999999
   PRINT(ROUND(2.675 * 100) / 100)  // 2.68 — 화면에서는 둘 다 반올림 경계값인데 방향이 다르다
   ```

3. **끝자리 0을 보여 줄 수 없다.** 숫자는 최단 표기로 찍히므로(spec v0.14.0) `3.40`은 `3.4`,
   `3.0`은 `3`이 된다. 금액이나 표처럼 자릿수를 맞춰야 하는 출력을 만들 수 없다.
4. **0 쪽으로 자르는 함수가 없다.** 음수에서 `FLOOR`는 −∞ 쪽으로 가므로 -3.48을 소수 한 자리로
   내리면 -3.4가 아니라 -3.5다.

곁가지로, JavaScript 런타임의 수학 함수는 인자를 검사하지 않는다. 레퍼런스는 오류로 멈추는데 JS는
엉뚱한 값을 낸다.

| 호출 | Java (레퍼런스) | JavaScript |
|---|---|---|
| `ROUND()` | `ROUND() missing argument 1` | `NaN` |
| `ROUND("x")` | `ROUND() requires numeric arguments` | `NaN` |
| `FLOOR(true)` | `FLOOR() requires numeric arguments` | `1` |
| `SUM("a", 1)` | `SUM() requires numeric arguments` | `0a1` |
| `MIN()` | `MIN() requires at least one argument` | `Infinity` |

## 2. 다른 언어

**자릿수를 받아 숫자로 돌려주는 함수**

| 언어 | 함수 |
|---|---|
| Excel | `ROUND(x, n)`, `ROUNDDOWN(x, n)`(0 쪽), `ROUNDUP(x, n)`(0에서 먼 쪽), `TRUNC(x, n)` |
| SQL (Oracle·PostgreSQL) | `ROUND(x, n)`, `TRUNC(x, n)` |
| Julia | `round`·`floor`·`ceil`·`trunc(x, digits=n)` |
| Python | `round(x, n)`만. 내림·버림은 자릿수를 받지 않는다 |
| JavaScript·Java·Go | 없음 (Java는 `BigDecimal.setScale(n, mode)`) |

음수 자릿수(`ROUND(1234, -2)` → 1200)는 Excel·SQL·Python·Julia가 모두 받는다.

**반올림 동점 규칙** (정확히 중간인 값)

| 규칙 | 쓰는 곳 | `2.5` | `-2.5` |
|---|---|---|---|
| 0에서 먼 쪽 | Excel·SQL `ROUND`, C `round`, Java `HALF_UP`·`String.format` | 3 | -3 |
| +∞ 쪽 | JavaScript·Java `Math.round` — 현재 ProperTee `ROUND(n)` | 3 | -2 |
| 짝수 쪽 | Python `round`, Julia `round` | 2 | -2 |

**무엇을 기준으로 자르나.** 플랫폼마다 다르다. 같은 1.005가 이렇게 갈린다.

- Java `String.format("%.2f", 1.005)` → `1.01`: 최단 십진 표기 `1.005`를 자른다.
- JavaScript `(1.005).toFixed(2)` → `"1.00"`, Python `round(1.005, 2)` → `1.0`: 이진값
  1.00499999999999989…를 자른다.

**문자열을 만드는 서식 함수**

| 언어 | 예 |
|---|---|
| C·Java·Go·Lua·bash | `printf("%-8s %8.2f", name, x)` |
| Python | `"{:<8} {:>8.2f}".format(name, x)`, f-string |
| Rust | `format!("{:<8} {:>8.2}", name, x)` |
| C# | `string.Format("{0,-8} {1,8:F2}", name, x)` |
| Excel | `TEXT(x, "0.00")`, `FIXED(x, 2)` |
| JavaScript | 없음 (`toFixed`, `padStart`, `Intl.NumberFormat`을 조합) |

서식 문자열은 두 계열이다. 값마다 타입 글자를 적는 printf `%` 계열과, 자리 표시 `{}` 뒤에 선택적
서식을 붙이는 중괄호 계열이다.

## 3. 제안 1 — 자릿수 인자

### 3.1 함수

| 함수 | 방향 | `3.48`, 1 | `-3.48`, 1 |
|---|---|---|---|
| `ROUND(n, [digits])` | 가까운 쪽 (동점은 §3.3) | `3.5` | `-3.5` |
| `FLOOR(n, [digits])` | −∞ 쪽 (내림) | `3.4` | `-3.5` |
| `CEIL(n, [digits])` | +∞ 쪽 (올림) | `3.5` | `-3.4` |
| `TRUNC(n, [digits])` (새 함수) | 0 쪽 (버림) | `3.4` | `-3.4` |

- `digits`는 남길 소수 자릿수다. 0은 일의 자리, 음수는 십·백 자리다: `ROUND(1234.5, -2)` →
  `1200`, `CEIL(1201, -2)` → `1300`.
- `digits`를 생략하면 지금과 같다. 결과는 정수이고, 32비트 범위를 벗어나면 `Integer overflow`다.
  `TRUNC(n)`도 같다(`TRUNC(-3.9)` → `-3`).

### 3.2 기준은 보이는 숫자

`n`을 `PRINT`가 보여 주는 십진수(최단 왕복 표기, spec v0.14.0)로 보고 그 자리에서 자른다. 결과는
잘린 십진수에 가장 가까운 수다.

```
PRINT(FLOOR(0.29, 2))    // 0.29 (곱셈 우회는 0.28)
PRINT(FLOOR(4.35, 2))    // 4.35 (곱셈 우회는 4.34)
PRINT(ROUND(1.005, 2))   // 1.01
PRINT(ROUND(2.675, 2))   // 2.68
```

- 사용자가 보는 숫자대로 동작한다. 이진값을 기준으로 하면 0.29는 실제로 0.28999…이므로
  `FLOOR(0.29, 2)`가 0.28이 된다. 짧은 소수의 약 절반은 이진값이 조금 작아서 이렇게 한 칸 아래로
  떨어진다.
- 두 런타임은 이미 같은 최단 표기를 찍는다(v0.14.0). 그래서 이 정의는 결과도 같게 만든다. 플랫폼
  내장 함수를 그대로 쓰면 1.005처럼 런타임마다 달라진다(§2).
- 잘린 십진수의 유효숫자가 15자리 이하이면 `PRINT`는 정확히 그것을 보여 준다:
  `ROUND(10 / 3, 2)`는 `3.33`으로 찍힌다.
- 부동소수점 계산의 결과도 보이는 그대로 다룬다. `0.1 + 0.2`는 `0.30000000000000004`로 찍히므로
  `CEIL(0.1 + 0.2, 1)`은 `0.4`, `ROUND(0.1 + 0.2, 2)`는 `0.3`이다.

### 3.3 반올림 동점

보이는 숫자가 정확히 중간일 때(`2.5`, `1.005`를 소수 둘째 자리로) `ROUND`가 갈 방향이다. 권장안은
**0에서 먼 쪽**이고, `digits`가 없는 `ROUND(n)`도 같은 규칙으로 바꾼다.

- `ROUND(2.5)` → `3`, `ROUND(-2.5)` → `-3` (지금은 `-2`), `ROUND(-1.005, 2)` → `-1.01`.
- 음수와 양수가 대칭이다: `ROUND(-x, d) == -ROUND(x, d)`. 금액을 다룰 때 중요하다. Excel·SQL·C와
  같고, 흔히 말하는 반올림(절댓값 기준 사사오입)과 같다.
- 깨지는 변경이다. 다만 바뀌는 것은 정확히 중간인 음수(-0.5, -1.5, -2.5 …)를 `ROUND(n)`한 결과뿐이다.
  오류 없이 값만 달라지므로 마이그레이션 노트에 적는다. 현재 fixture 중 이 경우를 고정한 것은 없다.
- 대안은 지금 규칙(+∞ 쪽)을 두 형태 모두 유지하는 것이다. 깨지지 않지만 `ROUND(1.005, 2)` →
  `1.01`, `ROUND(-1.005, 2)` → `-1`처럼 비대칭이다.

어느 쪽이든 두 형태는 같은 규칙을 써서 `ROUND(x, 0) == ROUND(x)`가 되게 한다(§8-1).

### 3.4 결과의 타입과 범위

- `digits`를 주면 결과는 항상 소수(decimal)다. `digits`가 0이어도 그렇다. 소수이므로
  `Integer overflow`가 없다: `ROUND(3000000000.7)`은 overflow이지만 `ROUND(3000000000.7, 0)`은
  `3000000001`이다. 표시는 정수와 같다(`ROUND(3.0, 2)` → `3`). 끝자리 0이 필요하면 §4의 서식을 쓴다.
- `digits`는 정수다. 정수 인자의 규칙대로 정수 값인 소수(`2.0`)는 받는다.
- 범위 제한은 없다(§8-2). 수가 가진 자릿수보다 크면 아무것도 바꾸지 않는다(`ROUND(3.48, 400)` →
  `3.48`). 수보다 큰 단위면 0이나 그 단위가 된다(`ROUND(3.48, -5)` → `0`, `CEIL(3.48, -5)` →
  `100000`). 최대값 근처에서 올린 결과가 수의 범위를 넘으면 산술처럼 `Infinity`다
  (`TO_NUMBER("1e308") * 10`이 `Infinity`인 것과 같다).
- `digits`가 있으면 `Infinity`·`NaN`은 그대로 돌려준다.

### 3.5 오류

| 경우 | 메시지 |
|---|---|
| 인자 없음 | `ROUND() missing argument 1` (지금과 같다) |
| `n`이 수가 아님 | `ROUND() requires numeric arguments` (지금과 같다) |
| `digits`가 정수가 아님 | `ROUND() digits must be an integer` |
| 인자가 셋 이상 | `ROUND() takes at most 2 arguments` |

세 번째 인자를 오류로 하는 것은 이 네 함수뿐이다. 지금 두 번째 인자가 조용히 버려지는 것과 같은
실수를 막기 위해서다. 다른 내장 함수의 남는 인자는 이번 범위 밖이다(§6).

## 4. 제안 2 — 서식 출력: `FORMAT`과 `PRINTF`

### 4.1 왜 `PRINT` 자체가 아닌가

`PRINT`의 첫 인자를 서식 문자열로 읽으면 지금 스크립트의 출력이 조용히 바뀐다. `PRINT("{}", x)`는
지금 `{} 5`를 찍는다. 서식 기호가 든 라벨도 흔하다. 그리고 `PRINT`는 첫 문자열이 라벨인지 서식인지
구별할 수 없다. 그래서 서식 인자를 받는 출력은 이름을 따로 둔다.

| 함수 | 하는 일 |
|---|---|
| `PRINTF(format, values...)` | `format`대로 만든 한 줄을 출력하고 `{}`를 돌려준다 |
| `FORMAT(format, values...)` | 같은 문자열을 출력하지 않고 돌려준다 |

`PRINTF(f, …)`는 `PRINT(FORMAT(f, …))`와 같다. C의 `printf`와 달리 `PRINT`처럼 줄을 끝낸다. 출력은
TeeBox의 실행별 stdout처럼 줄 단위로 모이기 때문이다. `FORMAT`은 파일에 쓰거나(`WRITE_LINES`)
결과에 담을 문자열을 만들 때 쓴다.

```
PRINTF("{} 개, 평균 {:.2f}", 3, 3.4)        // 3 개, 평균 3.40
PRINTF("{:<6}|{:>8.2f}|", "합계", 1234.5)    // 합계    | 1234.50|
line = FORMAT("{:,.2f}원", 1234567.891)     // "1,234,567.89원"
PRINTF("{:.1f}", TRUNC(3.48, 1))            // 3.4 — 버림은 §3의 함수로
```

### 4.2 서식 문법

중괄호 계열(Python·Rust)의 작은 부분집합이다. 각 부분은 Python에서와 같은 일을 하되, `PRINT`가 보여 주는
글자에 적용한다. 그래서 `true`(Python은 `1`), 정합 소수 `2`(Python `2.0`), `10000000000000000`(Python
`1e+16`)처럼 바탕 글자가 다르면 결과도 다르다.

| 자리 표시 | 뜻 |
|---|---|
| `{}` | 다음 값을 `PRINT`가 보여 주는 그대로. 문자열은 따옴표 없이, 배열·객체는 `PRINT`와 같은 표기 |
| `{:spec}` | 다음 값을 `spec`대로 |
| `{{`, `}}` | 글자 `{`, `}` |

`spec`은 `[정렬][0][폭][,][.자릿수f]`이다. 모두 선택이고 이 순서로 쓴다. 폭과 자릿수는 최대 세
자리다(`{:1000}`이나 `{:.1000f}` 같은 서식으로 거대한 문자열을 만들지 않게). `0`은 정렬이나 `,`와
함께 쓸 수 없다. Python에서 `{:<08.2f}`는 `-3.40000`처럼 0을 오른쪽에 채우고, `{:012,.2f}`는 채운
0에도 쉼표를 넣어 `0,001,234.50`을 만든다. 둘 다 단순한 채우기가 아니므로, 같은 뜻을 지키는 대신
에러로 둔다.

| 부분 | 뜻 | 예 → 결과 |
|---|---|---|
| 정렬 `<` `>` `^` | 왼쪽·오른쪽·가운데. 생략하면 수는 오른쪽, 나머지는 왼쪽 | `{:^6}`, `"ab"` → `"  ab  "` |
| 폭 | 최소 글자 수. 모자라면 공백으로 채우고, 넘쳐도 자르지 않는다 | `{:6}`, `42` → `"    42"` |
| `0` | 부호 뒤를 0으로 채운다 (수 전용) | `{:08.2f}`, `-3.4` → `"-0003.40"` |
| `,` | 정수 부분을 세 자리마다 쉼표로 나눈다 (수 전용) | `{:,}`, `1234567` → `"1,234,567"` |
| `.Nf` | 소수 아래 정확히 N자리 (수 전용). `ROUND(x, N)`과 같은 규칙으로 반올림하고 지수 표기를 쓰지 않는다 | `{:.2f}`, `3.4` → `"3.40"` |

- 폭은 `LEN`처럼 센다(UTF-16 단위). 한글처럼 터미널에서 두 칸을 차지하는 글자도 한 글자로 세므로,
  터미널에서는 표 정렬이 어긋날 수 있다. 문서에만 적는다.
- `.Nf`는 보이는 숫자를 기준으로 0에서 먼 쪽으로 반올림한다(§3). 그래서 Python과 다를 수 있다.
  `{:.2f}`에 `1.005`는 `1.01`(Python `1.00`), `{:.0f}`에 `2.5`는 `3`(Python `2`), `{:.1f}`에
  `-0.04`는 `0.0`(Python `-0.0`)이다. 0으로 반올림된 값에는 부호를 붙이지 않는다.
- `.Nf`는 크기가 커도 지수 표기를 쓰지 않는다: `{:.2f}`에 `1e21`은
  `1000000000000000000000.00`이다. `{}`는 `PRINT`와 같아서 `1e+21`이다.
- `Infinity`·`NaN`에는 `.Nf`·`,`·`0`을 적용하지 않고 그대로 쓴다. 정렬과 폭은 적용한다.

### 4.3 오류

엄격하게 실패한다. 나중에 문법을 넓힐 때(§8-5) 지금 오류인 형태에만 새 뜻을 주면 되므로, 기존
스크립트는 깨지지 않는다.

서식 전체를 값보다 먼저 검사하며, 아래 순서로 보고한다.

| 경우 | 메시지 (예) |
|---|---|
| `format` 없음 | `FORMAT() missing argument 1` |
| `format`이 문자열이 아님 | `FORMAT() requires a string format` |
| 알 수 없는 서식 (`{:x}`, `{1}`, `{name}`) | `FORMAT() invalid format: {:x}` |
| 닫히지 않은 `{` | `FORMAT() invalid format: unclosed {` |
| 짝 없는 `}` | `FORMAT() invalid format: unmatched }` |
| 자리 표시와 값의 개수가 다름 | `FORMAT() format has 2 placeholders, got 3 values` (1이면 단수: `1 placeholder`, `1 value`) |
| 수 전용 서식에 수가 아닌 값 | `FORMAT() {:.2f} requires a number, got string` |

`PRINTF`의 오류는 이름만 `PRINTF()`이고, 다른 내장 함수처럼 위치 없이 보고된다.

## 5. 호환성 — spec v0.30.0

- **`digits`.** 지금 두 번째 인자는 조용히 버려진다. 그 인자를 넘기던 스크립트는 이미 틀린 값을
  받고 있었고, 이제 그 인자에 뜻이 생긴다.
- **새 이름 `TRUNC`, `FORMAT`, `PRINTF`.** 대문자 이름은 예약되어 있어(v0.12.0) 스크립트 함수와
  겹칠 수 없다. 호스트가 같은 이름의 외부 함수를 등록했다면 이렇게 된다.
  - `TRUNC`·`FORMAT`: 지금 규칙대로 그 등록이 내장 함수를 대신한다.
  - `PRINTF`: `PRINT`처럼 인터프리터가 직접 처리하는 이름이 되므로 등록이 호스트 API 오류가 된다.
  - TeeBox는 셋 다 쓰지 않는다.
  - 무시할 함수는 이름마다 따로 막으므로, 출력을 막으려고 `PRINT`를 무시하는 호스트는 `PRINTF`도 무시해야
    한다(구현 후 검토에서 지적).
- **동점 규칙.** 0에서 먼 쪽으로 바꾸면(§3.3) 깨지는 변경이다. `ROUND(-2.5)`가 `-2`에서 `-3`이
  된다. 정확히 중간인 음수만 바뀐다.
- **JavaScript 수학 함수.** `SUM` `MAX` `MIN` `ABS` `FLOOR` `CEIL` `ROUND`가 레퍼런스와 같은 인자
  검사를 얻는다. JS에서 `NaN`이나 엉뚱한 값을 내던 호출은 오류가 된다.
- 문법 변경은 없다. Java 7/8 레거시 런타임은 고치지 않는다.

## 6. 기각한 대안

- **`PRINT`의 첫 인자를 서식으로 읽기**: §4.1.
- **모드 인자 하나로 자르기** (`ROUND(x, 1, "down")`): 문자열 모드는 오타가 나도 알아채기 어렵다.
  네 이름이 Excel·SQL·Julia와 같아 읽기도 쉽다.
- **이진값을 기준으로 자르기** (Python, JS `toFixed`): `FLOOR(0.29, 2)`가 `0.28`이 된다(§3.2).
- **숫자 전용 서식 함수** (`FORMAT_NUMBER(x, 2)`): `FORMAT("{:.2f}", x)`가 같은 일을 하고, 폭과
  정렬도 다룬다.
- **다른 내장 함수의 남는 인자도 검사하기**: 내장 함수 전체의 인자 개수 규칙은 따로 다룬다. 이번에는
  시그니처가 바뀌는 네 함수만 검사한다.

printf `%` 계열은 기각하지 않고 §8-3의 대안으로 남긴다.

## 8. 열린 질문

2026-10-23 사용자가 Python의 동점 규칙을 확인한 뒤("반올림 경계값의 경우 파이썬은 어떻게 되어있어?")

1. **동점 규칙**: 0에서 먼 쪽(권장. `ROUND(-2.5)`가 `-3`으로 바뀌는 깨지는 변경) / 지금의 +∞ 쪽
   유지(비대칭이지만 깨지지 않음) / 짝수 쪽(Python·Julia. 통계용이고 일상적인 반올림과 다름).
   Python 3의 `round`는 짝수 쪽이지만 이진값을 반올림하므로 `round(2.675, 2)`처럼 보이는 숫자로는
   경계값인 많은 값에서 규칙이 드러나지 않는다. 보이는 숫자를 기준으로 하는 이 설계에서는 경계값이
   훨씬 자주 드러나고, 짝수 쪽은 양수 `ROUND(2.5)`(3 → 2)까지 바꾼다. **결정**: 0에서 먼 쪽.

     어긋나면 오류가 된다.
