# 설계 초안: ALL-CAPS 함수 네임스페이스 예약

**상태: 채택 — 스펙 v0.12.0으로 출하 (2026-07-05 사용자 결정).** TeeBox(현재 유일한 사용처)가 운영 반영 전이라 breaking 부담이 낮은 지금이 모델을 고칠 적기라는 판단으로, 초안 작성과 동시에 구현 착수. 이슈 트래커 없이 세션 논의로 채택된 배치(v0.10.0 전례).

## 1. 문제 — 논의의 아크

이 초안은 "SLEEP을 키워드로 승격하면 어떤가"라는 제안에서 출발한 3단계 논의의 종착점이다.

1. **발단**: 동시성 구조(`multi`/`thread`/`monitor`)가 키워드인 언어에서 스케줄러와 상호작용하는 `SLEEP`이 함수인 것에 괴리감이 있다는 제안.
2. **실행 모델 분석**: ProperTee의 중단(suspension)은 await-계열(중단 = 특수 구문, 함수에 색깔)이 아니라 **Go-계열**(블로킹 호출은 함수 일반의 성질, 런타임이 멀티플렉싱)이다. `SLEEP`은 유일한 중단점이 아니다 — `SHELL`/`HTTP*`/파일 I/O/async 외부 함수 전부가 같은 계약(레퍼런스의 `Coop.blocking`: 바톤 해제 → 블록 → 재획득)으로 호출 스레드만 재우고 형제에 양보한다. `sleep`만 키워드화하면 "SHELL은 양보하지 않는다"는 잘못된 신호가 되고, 일관성을 지키려면 await류 함수 색깔로 가야 하는데 이는 완전 협력형 런타임이 명시적으로 거부한 설계다. **→ 키워드 승격 기각.**
3. **위화감의 근원 식별**: 남은 위화감의 실체는 SLEEP이 아니라 — **ALL-CAPS 네임스페이스가 "런타임/호스트에서 제공됨"을 신호하면서, 정작 스크립트 함수가 그 표면을 덮어쓸 수 있다**(spec v0.11.0이 확정한 스크립트-우선 shadowing)는 신호와 보장의 불일치였다. 키워드는 대체 불가인데 빌트인은 대체 가능하다는 비대칭.

## 2. 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| `sleep` 키워드 승격 | 스케줄링 동작 무변화(이미 인터프리터 디스패치·Coop.sleep). 중단점이 SLEEP만이 아니므로 모델 왜곡 — 일관성을 위해선 SHELL/HTTP에도 await류 표시 필요 → 함수 색깔 도입, 언어가 거부한 방향. 소문자 키워드 vs 대문자 빌트인 이중 체계 or `SLEEP` 제거 breaking. 호스트 샌드박스 API(`setIgnoredFunctions(["SLEEP"])`) 마이그레이션. 키워드가 구조(multi/thread/monitor)가 아닌 효과(PRINT류)에 쓰인 전례 없음(Lua `coroutine.yield`도 함수) |
| builtin-우선 회귀 (v0.11.0 이전 v1/js 순서) | v0.11.0에서 기각된 그대로 — 새 빌트인 추가가 기존 스크립트 함수를 **조용히** 가로챔(v0.10.0 OK/ERR에서 실제 발생한 위험) |
| 기존 빌트인 이름과의 충돌만 정의 시점 에러 | 반쪽 해법 — 스펙이 새 빌트인 `FOO`를 추가할 때마다 `function FOO`를 쓰던 스크립트가 그때 가서 깨짐(시끄럽게 깨지니 조용한 가로채기보단 낫지만 스펙 추가가 영원히 지뢰밭). 호스트별 외부 함수 집합이 달라 "같은 스크립트가 호스트에 따라 에러"가 되는 비결정성 |
| 툴링 경고만 (#8 `not` 우선순위 방식) | 비파괴지만 신뢰 미회복 — 독자는 여전히 `PRINT(x)`가 진짜 PRINT인지 스크립트 전체를 훑어야 앎 |

## 3. 채택안 — ALL-CAPS 함수 정의명 예약

> **규칙**: 스크립트의 함수 **정의명**이 `^[A-Z][A-Z0-9_]*$`(대문자로 시작하고 소문자를 포함하지 않는 이름)에 매치하면 **정의 시점 런타임 에러**.
>
> 에러 메시지(3 런타임 동일, 정의 위치 line:col 포함):
> `Cannot define function 'FOO': all-uppercase names are reserved for built-in and host functions`

효과:

- **관례가 보장이 된다.** ALL-CAPS = 런타임/호스트 제공이 문법적 사실이 됨 — 키워드처럼 대체 불가, 그러나 함수 형태는 유지(합성 가능: `SLEEP` 위에 대기 추상화를 스크립트로 구축; 호스트 차단 `setIgnoredFunctions` 불변).
- **미래 빌트인 추가와 스크립트의 충돌이 구조적으로 불가능**해진다 — v0.11.0의 목표(빌트인 추가의 비파괴성)를 해석 순서가 아니라 네임스페이스 분리로 달성하는 상위 해법.
- 이름 해석의 잔여 규칙(v0.11.0)이 실질적으로 소문자 영역에만 적용되어 단순해진다.

## 4. 결정 체크리스트 (초안 기본값으로 채택)

1. **패턴** = `^[A-Z][A-Z0-9_]*$`. 단일 대문자(`A`)도 예약. `_` 시작(`_FOO`)은 비예약(호스트 관례 `_PROPS`는 프로퍼티라 무관). 소문자가 하나라도 있으면(`Foo`, `getBALANCE`) 자유.
2. **변수/파라미터명은 비제한** — 함수와 변수는 별도 네임스페이스(일급 함수 없음), 호출 해석에 모호성이 없음. `MAX = 10` 합법 유지.
3. **시행 시점** = `function` 정의문 방문 시점의 런타임 에러. 파스타임 아님(문법 무변경 — ANTLR 재생성 불필요).
4. **호스트 외부 함수 등록은 비제한** (ALL-CAPS 권장 관례 문서화). 호스트가 소문자 이름을 등록하는 잔여 케이스에는 v0.11.0 해석 순서(스크립트 함수 우선)가 그대로 적용.
5. **v0.11.0 Name Resolution 절 유지 + 본 규칙 추가.** v0.11.0이 "누가 이기나"를 정했다면 v0.12.0은 "애초에 싸움이 성립 안 하게" 하는 것 — 순서 규칙 자체는 잔여 케이스에 여전히 유효.
6. **픽스처**: `104_user_function_shadowing` 제거(전제가 무의미해짐 — 번호 결번은 31 전례 있음), `75_range_step_eval_once` 갱신(`STEP`→`step_fn`, .expected 불변), 신규 `105_error_reserved_function_name`(정의 시점 에러·위치) + `106_function_name_case`(`Foo`/혼합 케이스 정의 합법, ALL-CAPS 호출 불변) → 레퍼런스 **103쌍**.
7. **버전**: 스펙 **v0.12.0** (breaking), propertee2-java **0.8.0**, propertee-java **1.4.0**, js는 무버전 관례 유지.

## 5. 영향 / 마이그레이션

- **Breaking**: ALL-CAPS 함수를 정의한 스크립트는 정의 위치를 지목하며 시끄럽게 깨짐. **코퍼스 전수 조사(2026-07-05)**: TeeBox `.tee` 스크립트 0건, 스펙 예제(EN/KO) 0건, js 샘플 0건, 픽스처 2건(75, 104)뿐. TeeBox는 운영 반영 전 — 문제 스크립트는 전수 확인·수정 가능(사용자 확인).
- **shadow-mocking 폐지**: v0.11.0 픽스처 104가 고정했던 "스크립트 함수로 빌트인 mock" 패턴이 불가능해짐. 대체: 호스트 레벨 외부 함수 주입(테스트 하네스가 하는 방식) 또는 소문자 래퍼 함수.
- **SLEEP 키워드 논의 종결** (§2). 중단 모델에 대한 사용자 궁금증("어떻게 재우나, 나도 만들 수 있나")은 LANGUAGE.md **"Blocking and Suspension"** 소절 신설로 해소(§6) — 빌트인은 런타임 프리미티브(ProperTee로 작성된 것이 아님), SLEEP/블로킹 호출이 중단 프리미티브, 대기 추상화는 그 위에 스크립트로 합성, 호스트는 async 외부 함수 계약으로 자기 중단 프리미티브 제작 가능.
